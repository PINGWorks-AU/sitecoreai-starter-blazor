## App.razor
In Blazor apps the `App.razor` file is typically used as the entry point, with the wrapping HTML elements. The code below shows a template `App.razor` for use with the Blazor SDK. Site stylesheets live in `MainLayout.razor` (see below), so `App.razor` holds only the document shell and the outlets the SDK needs.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <base href="/" />
    <ResourcePreloader />
    <AppInsights />   <!-- optional; renders nothing unless Application Insights is configured -->
    <ImportMap />
    <HeadOutlet />

    <!-- outlets used by the SDK -->
    <SectionOutlet SectionName="HeadLayout" />
    <SectionOutlet SectionName="HeadPage" />
    <SectionOutlet SectionName="SitecoreEditingScripts" />
</head>
<body>
    <Routes />
    <ReconnectModal />
    <script src="@Assets["_framework/blazor.web.js"]"></script>

    <!-- outlets used by the SDK -->
    <SectionOutlet SectionName="ScriptLayout" />
    <SectionOutlet SectionName="ScriptPage" />
</body>
</html>
```

`<AppInsights />` adds browser telemetry when Application Insights is configured. See [Application Insights](app-insights.md).

A `<SectionOutlet />` element can only be assigned once from within the hierarchy of components making up the Blazor page, that is, if two components write to a SectionOutlet with the same SectionName, only the content from the last one will come through.

For this reason we add the following SectionOutlet elements:

- `HeadLayout` / `ScriptLayout` - these allow a Razor layout (e.g. `MainLayout.razor`) to push site-wide CSS and scripts into the output HTML
- `HeadPage` / `ScriptPage` - these allow a Razor page (e.g. `Page.razor`) to push page-specific CSS and scripts into the output HTML
- `SitecoreEditingScripts` - the SDK itself writes to this outlet when the page is loaded inside the Pages editor. You do not push to it from your own components.

## Routes.razor

The default Blazor template generates a `Routes.razor` that uses the standard `<Router>` component. Replace it with the SDK's `<SitecoreRouter>` so that any URL not matched by an explicit `@page` directive falls through to Sitecore:

```html
<SitecoreRouter AppAssembly="typeof( Program ).Assembly" NotFoundPage="typeof( Pages.Status )">
    <Found Context="routeData">
        <RouteView RouteData="routeData" DefaultLayout="typeof( Layouts.MainLayout )" />
        <FocusOnNavigate RouteData="routeData" Selector="h1" />
    </Found>
</SitecoreRouter>
```

`<SitecoreRouter>` takes the same parameters as `<Router>` and adds two things:

- It includes the SDK assembly in `AdditionalAssemblies`, so the SDK's `SitecorePage` catch-all route (`/{*RequestPath}`) and its other pages are reachable during interactive navigation.
- It records an analytics page view on every navigation (see [Analytics and tracking](analytics-tracking.md)), then calls any `OnNavigateAsync` handler you supply.

The `NotFoundPage` parameter is used when neither an explicit Blazor route nor a Sitecore item matches the requested URL. The Starter Kit points it at the `Status` page; see [Error handling](error-handling.md) for the details.

## MainLayout.razor

`MainLayout.razor` is the default layout for every Sitecore-routed page. It pushes the site-wide stylesheets into the `HeadLayout` outlet; head and script content that varies with the page type belongs in your `Page.razor` template. A minimal layout looks like this:

```html
@inherits LayoutComponentBase

<SectionContent SectionName="HeadLayout">
    <!-- use 'Assets' to ensure fingerprinting; see https://learn.microsoft.com/en-us/aspnet/core/blazor/fundamentals/static-files -->
    <link rel="stylesheet" href="@Assets["app.css"]" />
    <link rel="stylesheet" href="@Assets[$"{AssemblyName}.styles.css"]" />
</SectionContent>

@Body

<!-- standard Blazor error bar -->
<div id="blazor-error-ui" data-nosnippet>
    An unhandled error has occurred.
    <a href="." class="reload">Reload</a>
    <span class="dismiss">🗙</span>
</div>

<SectionContent SectionName="ScriptLayout" />

@code {
    private static string AssemblyName = System.Reflection.Assembly.GetEntryAssembly()?.GetName().Name ?? string.Empty;
}
```

`{AssemblyName}.styles.css` is the component-scoped CSS bundle generated by Blazor. Its filename is the assembly name (the Starter Kit's project file replaces spaces with underscores), so reading it from the entry assembly keeps the link correct if you rename the project.

The Starter Kit's layout also renders the `<CookieConsent />` component, which drives the analytics consent cookies. See [Analytics and tracking](analytics-tracking.md).

The SDK injects its own editing chrome and editing scripts when needed: `SitecorePage` renders `<SitecoreEditingScripts />` into the `SitecoreEditingScripts` outlet while editing, so you do not add it to the layout yourself.
